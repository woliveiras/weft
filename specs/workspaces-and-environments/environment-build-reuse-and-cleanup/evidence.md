- 2026-11-13 · AC-003 · [Graph ID reuse after NATS cleanup failure](../../../server/internal/engine/broker_cleanup_nats_test.go) passed with SQLite and NATS JetStream 2.11.17 (`nats:2.11-alpine`). Closing the engine's NATS connection produced a real deletion error from the adapter. The graph disappeared from the store, ID reuse returned a conflict, and the original consumer still had one pending message. A new engine using a healthy connection and the same store completed the pending cleanup before reusing the ID. The recreated consumer had zero pending or in-flight messages and delivered only the newly published message. Run with `WEFT_TEST_NATS_URL` pointing to disposable JetStream and `go test -count=1 -run '^TestGraphIDReuseRecoversNATSBrokerCleanup$' ./internal/engine`. The run used cached images, an internal Docker network and a tmpfs JetStream store. The disposable container and network were removed; the running Compose stack was untouched. A follow-up run on 2026-11-13 used the cached `weft-review-go:git-http-backend` image and passed with `WEFT_TEST_NATS_URL` set to a disposable `nats:2.11-alpine` JetStream and `go test -count=1 -v -run '^TestGraphIDReuseRecoversNATSBrokerCleanup$' ./internal/engine` (0.105 s for the package). It observed the cleanup event and an empty consumer before reusing the graph ID.

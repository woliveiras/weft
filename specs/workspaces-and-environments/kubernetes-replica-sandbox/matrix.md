## Disposable cluster qualification, 2026-11-27

Kubernetes v1.37.0 (kind, Linux/arm64) ran under its own kubeconfig. The controller and sandbox claims were bound to two static PVs exposing the same directory on the disposable node. This exercises mount identity and retention on one node. A multi-node RWX backend still needs installation qualification.

- **M02.** Two replica identities received distinct pod UIDs and workspace markers. A deliberately mismatched mount failed its workspace check before the submitted command could create a file. Reading the sibling path failed. A write to the read-only replica failed while the writing replica retained its file across recreation. These cases exercise directory mounts. A separate checkout created with real `git worktree add` passed `git rev-parse` in the controller but returned exit 128 for `git status` in the pod. Its Git metadata lives outside the mounted checkout. Git write workflows using linked worktrees remain unqualified.
- **M03.** API access reviews granted the controller create/get/list/delete on pods and create on pods/exec in `weft-sandboxes`. The same operations were denied in `weft`. Reading Secrets and creating claims were denied in both namespaces. A legitimate pod passed server-side admission. Substituting the service account or image, enabling token mounting, or substituting a Secret volume was rejected. No service-account token was mounted inside the running sandbox. A request to the Eino Service by IP succeeded from the controller and timed out from the sandbox.
- **M04.** A command timed out, the timed-out pod was discarded, and a subsequent command saw the original workspace on a different UID. Cancellation and a disappearing pod produced infrastructure errors. Normal shutdown released disposable pods while the claims stayed bound.
- **M05.** `TestKubernetesEinoFactory` ran a compiled controller against two Go Eino service replicas, SQLite, the filesystem broker and a deterministic model. The fixture selected the Go runtime endpoint, configured the QA command and grant for `go test ./...`, and used a real disposable Go module. The developer received a review change request and a failing real Go test. The next QA run passed. The integration asserted the recorded exit status and failure text, zero integrator executions before approval and consumer acknowledgement afterward. The earlier two-controller PostgreSQL/JetStream callback rehearsal is recorded in [RUN-010](../../runtime-and-delivery/eino-runtime-migration/matrix.md).


The final serial runs of `TestLiveReplicaPods` and `TestKubernetesEinoFactory` passed in 15.73 s and 13.90 s respectively with the platform network policies enabled. Running both suites at once exceeded the single node’s schedulable CPU and one factory run reached its wait deadline. Sizing for simultaneously active pods is an installation requirement. The fixture does not qualify the stock Python distribution or multi-node storage.

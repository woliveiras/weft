end-to-end scenario uses three local Git repositories. The backend serves
`/ready`, the frontend client requests it and the infra fixture configures
the probe path. The fixture checks actual responses for both consumers.
SCM verification uses separate local bare remotes and a stateful PR adapter
fixture. Local Docker qualification covers full delivery, partial recovery,
cancellation, unchanged repositories and local-only completion.

## Reproducing the evidence

- Run `make test` for Go, Python, TypeScript and console component coverage. Run `make lint` and `make build` for static checks and binaries.
- Run the [Playwright scenario](../../../web/e2e/multi-repository-tasks.spec.ts) against the disposable `weft-e2e` controller with Chromium and Git available.
- Run `go test ./internal/api -run '^TestMultiRepositoryDockerTask$' -v -count=1` from `server/` with `WEFT_TEST_TASK_DOCKER_IMAGE` set to a local image containing Git, BusyBox with `nc` and `wget`, and a shell. The controller needs a Docker CLI and a test workspace visible at the same absolute path to the daemon. The [acceptance fixture](../../../server/internal/api/task_repositories_test.go) creates disposable SQLite records, projects and bare remotes. Its provider adapter simulates PR operations and lost responses. Live SCM accounts and native-process or per-replica multi-repository execution are outside this qualification.

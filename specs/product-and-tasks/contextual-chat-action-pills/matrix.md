# Contextual chat action pills — behavior and oracle matrix

The expected outcomes were written from
[ADR 0013](../../../docs/adr/0013-contextual-chat-action-pills.md) and the
[acceptance criteria](spec.md) before implementation. Integration checks
use a browser and a disposable Weft API/store with seeded roles and
resources. Inspect persisted turns, watches and review state where relevant.

| Criterion | Scenario | Observable outcome | Oracle provenance | Planned verification |
| --- | --- | --- | --- | --- |
| AC-001 | Open a ready chat and toggle Mais with all categories eligible | The first row reads Tasks, Agents, Workflows, Mais. A single text-only Mais reveals the four specified secondary categories in order. Administration is accessible in manual navigation only within this entry flow. | spec-derived | Unit check for labels, order and disclosure state. Browser check for open, close and manual navigation. |
| AC-001, AC-004 | Type a request while exploring an incomplete branch, then leave the guide | Typed text survives. Its accepted turn contains only the intended text. Slash completion and the existing send shortcuts still work. | spec-derived | Unit check for incomplete context and slash completion. Submit a free-text request through the browser and reopen its saved turn. |
| AC-002 | Explore each category as an eligible operator or administrator | Each applicable action in AC-002 is reachable. A manual link names its destination. Return from settings restores the unsent draft, branch and focus. | spec-derived | Unit check for the action catalogue and eligibility. Browser navigation to each configuration area and back with a partly written request. |
| AC-002, AC-003 | Inspect models as a viewer, then lose access to a selected resource in another session | Inspect and configure have distinct eligibility. Current access governs lookup and submission. A stale choice cannot start an effect or reveal inaccessible inventory. | spec-derived | Unit check for role and stale-choice states. Real API role-boundary test and browser submission after access changes. |
| AC-003 | Search for two tasks with the same title and choose the second | Both tasks show a title, state and distinguishing ID suffix. The draft shows the full ID. Only Send and follow or its keyboard shortcut starts the selected watch. | spec-derived | Unit check for candidate labels and stable selection. Browser-to-store watch check with duplicate titles. |
| AC-003 | Search returns no matches, an incomplete result, or a dependency failure | Each outcome is distinguishable. A lone partial match needs a choice. Retry or refinement retains the draft and can reach the intended resource. | spec-derived | Unit check for each state. Exercise empty inventory and interrupted lookup followed by recovery against the fixture service. |
| AC-004 | Pick a task, go back, change category, clear the choice, and switch chat or identity | Dependent selections clear. The user's text survives edits within the draft. Other drafts and identities receive none of its context. Pre-send browsing creates zero sessions, turns, model calls and watches. | spec-derived | Unit check for draft transitions. Compare API/store state and fixture provider call count before and after guided browsing. |
| AC-004 | Send a complete follow request without prose, then repeat with extra text and a lost acknowledgement | Each distinct request records one user turn with the intended action and target. Optional text survives. Retrying the same request creates no duplicate watch or message. | spec-derived | Unit check for complete intent and send shortcuts. Browser/API retry using the accepted request key and inspect the stored outcome. |
| AC-004 | Prepare a catalog agent creation through the guide | Browsing creates no proposal. Send opens the ordinary review. The agent is created only after authorized confirmation. | spec-derived | Unit check for prepare versus confirm. Browser-to-catalog check before Send, after Send and after confirmation. |
| AC-005 | Use keyboard, screen reader and a narrow touch viewport | Mais announces its state, Escape returns focus, Back restores the originating choice and all labels and the composer remain reachable. | spec-derived | Unit check for accessible names and focus transitions. Browser keyboard and narrow-viewport paths plus manual screen-reader and touch checks. |
| AC-001, AC-004 | Open a model-unavailable installation or an archived conversation | The established recovery action remains reachable. An archived chat cannot submit a guided request. | spec-derived | Unit check for readiness and archive states. Open both fixture states through their normal chat entry points. |

## Delivery evidence

| Criteria | Executed coverage |
| --- | --- |
| AC-001, AC-002 | [Guide component tests](../../../web/src/components/ChatActionGuide.test.tsx) exercise category order, disclosure, role-specific settings, archived chats and model recovery. [Browser journeys](../../../web/e2e/chat-session.spec.ts) exercise all four manual handoffs, Back, retained input and focus. [Project preference tests](../../../web/src/components/ProjectsPage.test.tsx) check the selected ID when project names coincide. |
| AC-003 | [API/store integration tests](../../../server/internal/api/chat_picker_test.go) verify structured task metadata for duplicate titles and exact IDs, bound partial results, deny an anonymous lookup and reject a vanished target even when another record's title matches its ID. The browser recovers an interrupted lookup and submits free text from an incomplete branch. |
| AC-004 | [Exact command tests](../../../server/internal/chat/picker_test.go) and the API/store tests cover invalid targets, notes and idempotent replay. The browser checks the persisted watch for the chosen duplicate, reads catalog state before and after confirmation, and switches identity with an unsent draft. The guide component checks both send shortcuts and request-key reuse after a lost acknowledgement. |
| AC-005 | The narrow Chromium journey scrolls the results while keeping search in place, changes the task with notes intact, and sends by keyboard at 390 px. The manual settings journeys verify focus on return. Component tests exercise disclosure state and Escape. Physical-device touch, a screen-reader walkthrough and unaided task completion with participants remain to be qualified. |

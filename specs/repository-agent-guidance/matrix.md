# REPO-GUIDANCE behavior and oracle matrix

The maintainer approved the decisions in the governing spec on 2026-11-11,
before implementation. The oracles below are spec-derived from those decisions
and the named acceptance criteria. Evidence remains pending until exercised.

| Criterion | Scenario | Observable oracle | Provenance | Planned verification | Evidence |
| --- | --- | --- | --- | --- | --- |
| AC-001 | Opted-in real checkout and separate replicas (D-01) | Each execution sees only its own clone/worktree paths and bytes. Root guidance uses the first present unblocked candidate. An invalid chosen file produces an omission. Immediate packages appear in the catalogue. Nested files, imports and other unsupported sources contribute no guidance. | spec-derived (D-01, AC-001) | Discovery unit and clone/worktree engine integration | Pending |
| AC-002 | Defaults, inheritance, disable, source blocks, and concurrent saves (D-02) | Existing and new graphs default off. The node may inherit, disable or narrow. Blocks cover alias and canonical origins before content load, with no digest for unread content. Viewer and operator saves are denied. Stale admin saves conflict. | spec-derived (D-02, AC-002) | Policy unit, graph API/store integration and browser admin preview | Pending |
| AC-003 | All composition layers and equal-rank repository skills (D-03) | Model context and Activity follow repository skills, root instruction, installation defaults, selected console skills, legacy steering, agent prompt, operator input. Bytewise canonical paths break otherwise unordered ties. Existing declared order is preserved. | spec-derived (D-03, AC-003) | Composition unit and engine/model-boundary integration | Pending |
| AC-003 | Console/repository and distinct repository name collisions (D-04) | Eligible selected console ID shadows the matching repository name. After alias deduplication, repository roots prefer .agents, .claude, .github, then canonical path. Shadowed bodies are unread and audit records reasons. | spec-derived (D-04, AC-003) | Collision unit and registry/worktree engine integration | Pending |
| AC-004 | Catalogue, reverse-order activation and a single requested reference (D-03, D-06) | Initial context has names, descriptions and identities. Requested bodies and reference appear only after selection and retain their source precedence. Unused bodies and sibling references never enter context. Console reads identify the selected revision. | spec-derived (D-03, D-06, AC-004) | Composition and activation unit tests, native model-boundary integration | Pending |
| AC-004 | Malformed metadata, missing, oversized or denied reference and exhausted budgets (D-06) | Explicit outcomes, whole optional entries, mandatory priority, deterministic admission, no unapproved bytes. 16 KiB per body/reference, 2 KiB per package metadata, 128 candidates per family and catalogue items per execution, 16 distinct references and 8,192 cumulative bytes with framing. | spec-derived (D-06, AC-004) | Boundary unit tests and real filesystem/engine integration | Pending |
| AC-004 | Identity, metadata or source eligibility changes before activation (D-05) | Live revalidation omits mismatches and reports the reason. Valid reads record the digest of the exact bytes delivered. | spec-derived (D-05, AC-004) | Identity unit tests and worktree replacement integration | Pending |
| AC-005 | Clean checkout with canonical Weft fixture and a relative alias (D-01, D-04, D-05) | sdd-specification appears once, a requested package reference loads, and Activity records alias, lock declaration, metadata digest and full-file digests. Blocking either root prevents bypass via the alias. | spec-derived (D-01, D-04, D-05, AC-005) | Alias/lock unit tests and real Git fixture/store/engine integration | Pending |
| AC-005 | Missing, invalid, unsupported or stale lock (D-05) | Advisory outcomes are explicit, absent versions are not guessed and no install, network read or lock write occurs. | spec-derived (D-05, AC-005) | Lock parser unit and disposable checkout integration | Pending |
| AC-006 | Escape, leave-and-return, broken/cyclic symlink, special file or swapped target (D-05) | Every hop and opened object stay in policy. Unsafe bytes are neither returned nor hashed. Special files cannot hang the loader. Individual body/reference links and steering links are rejected. | spec-derived (D-05, AC-006) | Path unit cases and real filesystem race integration | Pending |
| AC-006 | Guidance requests tools, credentials, file mutation, push or PR. Agent also reads or edits an independently granted file. | Existing gateways still deny or approval-gate operations. Guidance creates no grants or approvals. Granted edits still work and normal file reads do not activate a skill. | spec-derived (AC-006 and authority invariants) | Policy unit and engine/file/SCM gateway integration | Pending |
| AC-007 | Viewer opens opted-in execution in Activity (D-07) | Saved history shows effective order and all sources, console revisions, validated relative paths, stage digests, bounded descriptions, catalogue/body/reference stages and omissions. New entries have no body copies and legacy snapshots remain readable. Unauthenticated or unauthorized callers are denied. | spec-derived (D-07, AC-007) | Audit unit, API/store integration and Chromium Activity journey | Pending |
| AC-007 | Edits, cancellation, restart, failed read and uncertain dispatch (D-07) | Historical identities and outcomes survive. Prepared, confirmed, indeterminate and failed outcomes are distinct. Read records share the execution's retention. | spec-derived (D-07, AC-007) | Transition unit and real engine/store restart integration | Pending |
| AC-008 | Graph without the new opt-in and legacy executions (D-02, D-06, D-07) | Existing context, eager managed bodies, steering order and links policy remain compatible. Unavailable history is distinct from an empty recorded set. | spec-derived (D-02, D-06, D-07, AC-008) | Serialization/loader unit and upgrade/engine integration | Pending |
| AC-008 | Unsupported runtime, persistence failure and retried read (D-06, D-07) | Unsupported runtime fails before dispatch. Policy or audit failure never yields unrecorded guidance. Retrying an applied read adds neither duplicate application nor a second charge. | spec-derived (D-06, D-07, AC-008) | Error and budget unit tests plus fault-injected engine/store integration | Pending |

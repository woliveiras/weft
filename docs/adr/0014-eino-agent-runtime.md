# 0014 — Use Eino for native turns and ship Go workflow agents

**Status:** Proposed · **Date:** 2026-11-27 · **Decision owner:** Weft maintainers

## Decision

Use Eino in two places. For a catalogue agent or inline graph node with `runtime.kind: native`, run a typed Eino graph inside `weftd` to coordinate a single model/tool turn. For the bundled external agents, ship a Go service running Eino graphs behind the existing Runtime Protocol v1. Weft owns replica scheduling, gateways, authorization, approval records, message routing and acknowledgements for both paths. An existing native agent keeps its published definition, bindings, grants and isolation when its turn implementation changes.

The target is a Weft distribution that builds, tests, installs and runs its bundled workflows without Python or LangGraph. The maintainer confirmed a single-user installation and no projects relying on the Python SDK or on Python in the default sandbox. Plan a direct cutover after equivalent checks pass. Runtime Protocol v1 remains open to independently supplied services in any language.

This is a proposal for implementation. The review covered the control plane, runtime protocol, native and Python agents, storage and broker boundaries, operator surfaces, deployment and test harnesses at revision `cd2c6de`. The dependency and packaging inventory was reviewed at `e93048f`. Both execution paths and the removal below are proposed work.

## Context and decision drivers

[RUN-010](../../specs/runtime-and-delivery/eino-runtime-migration/spec.md) defines migration acceptance and the [verification matrix](../../specs/runtime-and-delivery/eino-runtime-migration/matrix.md) tracks the scenarios to qualify before cutover.

Console Chat has a separate integration decision. Its proposed in-process turn uses the operator's session and reviewed operations. Native workflow turns receive execution-scoped capabilities through the engine. External turns receive their scoped HTTP callbacks. [ADR 0015 — Eino for Console Chat](0015-eino-console-chat-turns.md)

There are two graphs with different lifetimes. A **Weft graph** is a versioned operator document. Its nodes may run concurrently on different controllers. Channels, consumer groups, replica leases and message history survive the process that handled a turn. An **Eino graph** is Go code compiled by an agent author. It can branch on a model response, call a tool and loop until it can produce a result. An Eino turn can choose its next internal step and construct an output. Weft decides which downstream replica receives that output and when it runs. [Architecture](../architecture.md) · [Replica leases](0002-reconciler-and-leases.md) · [Broker delivery](0003-pull-broker-abstraction.md)

The product needs to continue after a human decision. Reopening a completed execution to change a past decision and compare branches is outside the stated use case. Important constraints are local operation, existing workflow compatibility, bounded turns, one authoritative approval record and the ability to remove the dependency. Weft already qualifies a real Python LangGraph agent through the same protocol. Its fixture exercises provider selection and inference. An Eino agent that executes tools needs its own qualification. [Runtime decision](0004-runtime-protocol.md) · [Existing LangGraph evidence](../provider-langgraph-validation.md)

## Options considered

| Option | Benefit | Cost and disposition |
| --- | --- | --- |
| Use today's native Go runtime | Already supports model/tool loops, live model output and native coding features. Lowest operational cost. | Use it as the behavioral baseline for the in-process migration. |
| **Eino behind Runtime Protocol v1** | Agent authors control the graph in Go. Each service can be built, upgraded and removed independently of Weft. | Selected for bundled external agents and Go extensions. It costs one service, HTTP calls and a Go implementation of the wire contract. External-runtime restrictions apply. |
| **Eino inside the existing native runtime** | Uses execution-local guidance, live output and tool gateways through the existing Go interfaces. | Selected for native turns. This adds Eino to the server binary. A separate runtime kind would require changes to graph validation, saved definitions and the editor. |
| Use the Python LangGraph adapter | Already has a framework adapter and an end-to-end provider harness. | Retire the bundled adapter after the Go replacement reproduces its protocol behavior and test coverage. |
| Compile the platform workflow into Eino | A single graph vocabulary could serve authors and operators. | Would require rebuilding or mapping broker fan-out, replica leases, human gates and recovery. The proposed agent needs none of that duplication. |

## Native agents created in the catalogue or workflow editor

The operator publishes an agent version or saves an inline node exactly as today. During a turn, the engine supplies `TurnInput`, the execution context and `TurnEnv` to `native.Runtime.Turn`. Compile the Eino graph once, then allocate its conversation, counters and tool results per invocation. The proposed graph prepares guidance and fits the context, calls the model through `chatLive`, then branches on the response. A final answer goes to the existing result and stop-signal handling. A tool request goes to the existing dispatcher, which executes calls in order and feeds results back to the next model round. A review yield ends the turn immediately. Keep immutable PR analysis on its restricted path. [Native turn](../../server/internal/runtime/native/native.go) · [PR analysis](../../server/internal/runtime/native/pr_analysis.go) · [Catalogue workflow](../features/agents/README.md)

Preserve context compaction, small-model argument correction, the round limit, streaming, blocked/finish signals, delegation accounting and progressive guidance. Eino counts graph steps, while Weft counts model rounds and tool invocations. Carry the existing counters through the graph and test the boundaries separately. Unit tests should compare scripted outcomes and call order with today's loop. Engine integration must exercise the real gateways, including grant denial, budget exhaustion, cancellation, output routing and review yield before any remaining tool calls. [Native turn tests](../../server/internal/runtime/native/native_test.go) · [Streaming integration](../../server/internal/engine/streaming_integration_test.go) · [Review integration](../../server/internal/engine/review_integration_test.go)

## External agent pilot

The operator starts the optional service, registers or selects an existing model provider, and saves a workflow using the usual graph editor, API or CLI. The **External** runtime field selects the HTTP adapter. **Framework** is a free-text label. **Endpoint** locates the service and **agent** selects its registered program. Setting the label alone does not install or dispatch anything. An explicit provider lets Weft check availability before starting. [Graph normalization and validation](../../server/internal/graph/graph.go) · [Provider preflight](../../server/internal/engine/control.go) · [Node editor](../../web/src/components/NodePanel.tsx)

Proposed pilot graph. The service name is private to the example deployment. `pilot-model` stands for a configured provider instance. The fixture places a document in the granted directory and sends one `summary.requested` message containing its relative path.

```yaml
apiVersion: weft.io/v1
kind: Graph
metadata: {id: eino-summary, name: Eino summary pilot}
spec:
  nodes:
    - id: summarize
      runtime: {kind: external, framework: eino, agent: summarize, endpoint: "http://eino-agent:8000"}
      model: {provider: pilot-model}
      prompt: Summarize the requested document for operator review.
      loop: {mode: event, batchSize: 1}
      limits: {turnTimeout: 90s, maxToolCalls: 3, maxTokens: 4000}
      tools: [{name: filesystem.read, paths: ["docs/**"]}]
    - id: accepted
      runtime: {kind: echo}
      loop: {mode: event}
  channels:
    - {id: requests, to: [summarize], types: [summary.requested]}
    - {id: summaries, from: summarize, to: [accepted], types: [summary.proposed], approval: true}
```

For example, a `summary.requested` payload of `{"path":"docs/design.md"}` produces a `summary.proposed` payload shaped like `{"sourceMessageId":"<input message ID>","summary":"<reviewable text>"}`. The agent takes the source ID from the Weft envelope. The operator sees the execution and its usage in Runs, and the held message in Approvals. Approval releases the message to `accepted`. Rejection records the decision and withholds delivery. The producing turn has already finished, so the operator can return after the agent has restarted. The terminal echo node makes delivery observable without giving the pilot a write capability. [Channel publication and decisions](../../server/internal/engine/publish.go) · [Approvals UI](../../web/src/components/ApprovalsView.tsx)

## Execution from admission to acknowledgement

1. **Admit the turn.** A graph start or an admitted task reaches the existing engine. The external runtime checks `GET /v1/health` at replica preparation. The controller holding the replica lease claims the input, creates an execution, applies the node's limits and applicable gates, builds the instruction snapshot, and sends `POST /v1/turn` with a callback capability scoped to this execution. Task starts retain reviewed workflow, repository and policy scope. [Task admission](../../server/internal/taskrun/manager.go) · [External transport](../../server/internal/runtime/external/external.go) · [Turn lifecycle](../../server/internal/engine/turn.go)
2. **Enter the Eino program.** At service startup compile a typed `compose.Graph` for each supported agent. A compilation failure keeps the service unready. On each turn validate the agent, callback and expected input, allocate fresh state, and invoke the graph with the HTTP request context. The pilot path is **validate request → read document → call model → validate summary → return**. Additional tool requests can follow a bounded branch back to the model. Use `compose.WithMaxRunSteps` as an internal cycle guard alongside Weft's time, token and tool-call limits. Share only immutable graph definitions between concurrent requests. [Eino compose API, v0.9.23](https://pkg.go.dev/github.com/cloudwego/eino@v0.9.23/compose)
3. **Call through Weft.** The read node invokes `POST /tools/filesystem.read` under the execution callback. The model node sends Weft's `ChatRequest` to `POST /llm/chat`, using the node's selected model, system preamble, composed prompt and relevant input. The proposed adapter uses typed Eino lambda nodes around protocol operations. Keep tool schemas, call IDs, JSON arguments, opaque `providerData` and the link from each tool result to its call intact across model rounds. The gateway rechecks grants, sandbox policy, budget and cancellation. The external model callback returns a whole response. Bounded progress messages may use `POST /output`. [Callback handlers](../../server/internal/api/internal.go) · [Model wire types](../../server/internal/llm/llm.go) · [Tool gateway](../../server/internal/tools/gateway.go)
4. **Finish once.** Return a `TurnResult` with a summary and one `summary.proposed` emit containing the originating message ID and the validated text. Use the result as the sole emit path in the pilot. Report zero runtime-local usage and tool calls because the gateway already counted them. Propagate cancellation, invalid output, failed tools and provider failures to the runtime boundary. A failed model response must never produce a proposed summary. [Turn contract](../../server/internal/runtime/runtime.go) · [Budget controls](../../specs/providers-and-integrations/monetary-usage-and-budget-controls/spec.md)
5. **Publish and decide.** The controller revokes the callback, routes the result, persists the held output and acknowledges the claimed input after publication or durable hold. On decision, Weft handles the held message and records its disposition. When publication fails during the original turn, Weft backs off and redelivers the input, up to its delivery limit. Partial publication and earlier model charges can survive failure. The consuming application needs a stable business key such as source message ID plus logical output type if duplicate effects matter. [Engine publication tests](../../server/internal/engine/publication_integration_test.go) · [Execution model](../execution-model.md)

## State, approval and failure boundaries

| Situation | Proposed behavior and operational consequence |
| --- | --- |
| Service exits mid-turn or Weft cancels the run | Propagate the request context through every graph node and callback. Release request-local state. The engine owns cancellation and broker redelivery. A subsequent attempt gets a fresh execution ID and token. Avoid adapter retries of model calls or side-effecting tools after an ambiguous response. |
| Human approval takes hours | Use the outgoing channel gate above. The approval and message survive independently of the Eino process. The current decision hook logs a broker failure after approval. An approved record alone does not prove downstream delivery. Compare the message ID and consumer history before any operator recovery. [Publication hook](../../server/internal/engine/publish.go) |
| A workflow needs review of a specific workspace candidate | Use Weft's existing Docker-backed `review.request` grant where supported. A tool result with `yield: true` ends the entire turn immediately, including any queued tool calls and emits. The engine discards that turn's outputs. The review manager persists the candidate and decision, and its outbox supplies a later turn with the review result and a fresh capability. A blocking `/ask` is for a question within the current turn deadline. [Review protocol](../runtime-protocol.md#yielding-for-durable-human-review) · [Review implementation](../../server/internal/review/manager.go) |
| A turn is redelivered or two replicas run concurrently | Keep per-turn messages and credentials in request-local memory. The callback KV namespace is shared by graph and node, with separate reads and writes. It is unsuitable as an atomic deduplication ledger. The pilot needs no KV writes or database migration. Weft owns approvals, executions, usage and audit history. [State implementation](../../server/internal/engine/turn.go) |
| An upgrade happens while a decision is pending | The pilot persists a Weft message with an application-owned payload. Keep its reader compatible with queued payloads. Eino checkpoints serialize framework execution state, while Weft worktree checkpoints capture file changes. Neither is needed to release a held summary. Revisit storing Eino checkpoints only for a concrete need to resume inside one agent invocation, with a recovery identity, retention policy and cross-version restore test. [Worktree checkpoints](../../server/internal/engine/checkpoints.go) · [Eino checkpoint compatibility](https://www.cloudwego.io/docs/eino/core_modules/chain_and_graph_orchestration/checkpoint_interrupt/) |

## Retiring the bundled Python and LangGraph dependencies

Start with the external reviewer. Port its `analyse → decide` graph as two typed Eino nodes. For each `code.ready` input, `analyse` reads the listed files through the tool gateway and requests the model verdict through the model gateway. `decide` applies the existing Go-portable rules: an empty file set, an unreadable or empty file, or a TODO forces changes even when the model approves. Preserve the current heuristic when the model supplies no usable verdict. Emit the original item with verdict and comments as `review.approved` or `review.changes_requested`. Test both outcomes, multiple inputs, ignored message types and empty input. The workflow channels still deliver the result to QA or back to the developer. ### Kubernetes controller identity

The maintainer selected stable per-controller callback addresses for this migration. A two-replica StatefulSet and a headless Service provide `weftd-0.weftd-callback` and `weftd-1.weftd-callback`. The agent checks the advertised HTTP origin and execution path before sending the capability. The existing public controller Service still balances API traffic. The private callback returns to its originating controller. [Manifests and migration procedure](../../deploy/kubernetes/README.md#controller-callbacks-and-upgrades)

## Consequences and ownership

External agents gain independent upgrades and require a reachable service. Native turns add Eino to the server build and share its upgrade cycle with Chat. The platform team owns protocol compatibility and evidence that usage and decisions still reconcile. Before wider use, compare the same fixture against an equivalent plain Go external turn. Record end-to-end latency, model/tool call counts, peak memory at the target concurrency, and the agent/image size. Separate framework overhead from inference latency. These measurements are open.

CloudWeGo originated at ByteDance. The Apache 2.0 license allows continued use and maintenance of versions received under its terms. Long-term maintainer capacity, API compatibility and the cost of carrying patches remain adoption risks. Keeping Eino imports at the orchestration boundaries and durable data in Weft allows either implementation to return to plain Go behind the same contracts. The service operator can also retain the last qualified version during an upstream change. ## Confirmation, rollout and rollback

For the implementation, run `go test -race ./...` within the proposed agent module and wire its checks into `make test`, `make lint` and `make build` at the root. Keep `make test-e2e-providers` as a browser-to-provider regression and port its runtime fixture to Go/Eino. The Eino integration must execute the real Go service and compiled graph so that a passing Python fixture cannot mask a broken Go adapter.

| Stage | Evidence required to proceed |
| --- | --- |
| 1. Contract and unit tests | Test agent dispatch, invalid input and tool arguments, message/tool-call round trips, provider metadata, denied and failed tool responses (including HTTP 200 with `isError`), immediate yield, exhausted step/tool limits, cancellation and sanitized errors. Run concurrent invocations with separate callback capabilities under Go's race detector. Check that a failed turn returns no emits. |
| 2. Local integration | Run a real compiled Eino service, Weft controller, SQLite, filesystem broker and a deterministic model endpoint. Start the example through Weft. Assert selected model, actual granted file read, rejection outside the granted path, single accounting per call, pending approval, downstream delivery after approval and no delivery on rejection. Compare the execution, message and approval IDs across API reads. Reuse the existing provider harness pattern. [Provider integration](../../server/internal/api/providers_test.go) · [LangGraph harness](../../server/cmd/weft-provider-e2e/main.go) |
| 3. Recovery and coexistence | Interrupt a request, restart the adapter, test a stale callback, fail publication and observe retry/dead-letter behavior. Restart the controller while approval is pending and decide it on the new instance. Exercise duplicate input and two replicas with different credentials scoped to each execution. Demonstrate that a pending v1 payload completes after an agent upgrade. During development use the existing suites as the baseline, then run their Go equivalents and the browser provider journey in the clean qualification environment. [Callback lifecycle](../../server/internal/engine/callback_lifecycle_test.go) · [Publication regressions](../../server/internal/engine/publication_integration_test.go) |
| 4. Operator pilot | In a disposable profile, save the graph from the console, inject a fixture request, inspect cost and tool evidence, reject one result and approve another. Record versions, topology, resource measurements and remaining limitations. Exercise Docker candidate review separately before advertising it for Eino. Record implementation acceptance and evidence under the [specification index](../../specs/README.md). |

Exercise the service first on the pilot workflow, then qualify the full factory before replacing its image. Switch the native turn implementation independently and roll it back with the previous qualified server binary. Before expanding, identify an owner for dependency upgrades and qualify each installation topology that will be advertised. Roll back by stopping new admissions to the pilot, draining active turns and reconciling queued inputs and pending decisions. Keep the graph and channel IDs available until held messages settle, because the decision hook resolves the current channel at decision time. Restore the previous qualified binary or route new work to the previous version of the workflow. Verify message history and accounting before stopping the unused service. No database downgrade is involved.

Revisit the chosen boundary if a new external agent needs native-only guidance or durable mid-turn resumption, or if either implementation misses measured latency requirements. Acceptance of this ADR, rollout ownership and performance targets for a wider deployment remain maintainer decisions.
